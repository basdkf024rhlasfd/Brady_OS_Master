## Purpose

The Agent & Rule Creation Council is the first formal governance body within OS 2.0, responsible for:

1. **Agent Creation** — Approving new agents, their SOPs, and wiki profiles
2. **Rule Amendments** — Reviewing and approving changes to Agent Rules & Amendments
3. **Doctrine Coherence** — Ensuring new agents and rules align with OS 2.0 philosophy
4. **Quality Standards** — Maintaining the Gold Medal Standard for agent specifications

## Council Membership

| Member | Role | Expertise | Vote Weight |
|--------|------|-----------|-------------|
| **Phil** | Philosophical Auditor | Doctrine coherence, long-arc meaning, assumption testing | Full |
| **Cornelius** | System Architect | OS structure, database schemas, canonical surfaces | Full |
| **Musashi San** | Craft Arbiter | Spec quality, pattern recognition, gold medal standard | Full |
| **Claudine** | Operational Voice | Day-to-day reality, country-level implementation | Full |

### Why These Members

- **Phil** ensures new agents don't violate founding doctrine or create authority confusion
- **Cornelius** ensures new agents integrate properly with existing OS infrastructure
- **Musashi San** ensures specs are precise enough to execute without ambiguity
- **Claudine** ensures agents serve real operational needs, not theoretical elegance

## Powers & Authorities

### The Council CAN:

1. Approve new agent creation (SOPs, Wikis, Context entries)
2. Approve rule amendments to existing agents
3. Reject proposals that violate doctrine or quality standards
4. Request revisions before approval
5. Deactivate agents that are no longer serving their purpose
6. Establish agent standards and templates

### The Council CANNOT:

1. Override Brady's veto — Commissioner authority is absolute
2. Change OS 2.0 founding doctrine — that requires Commissioner action
3. Create Programs or Projects — that's operational, not governance
4. Execute tasks — the Council governs, it doesn't operate

## Decision Process

### Standard Proposal Flow

1. **Proposal Submitted** — Any agent or Brady can submit
2. **Phil Review** — Philosophical coherence check
3. **Cornelius Review** — Structural integrity check
4. **Musashi San Review** — Quality check (gold-medal worthy?)
5. **Claudine Review** — Operational check (serves real needs?)
6. **Council Vote** — Majority required for approval
7. **Brady Review** — Commissioner may approve, veto, or request changes

### Voting Rules

- **Quorum:** 3 of 4 members must participate
- **Approval:** Simple majority (2+ votes)
- **Veto Override:** Not possible — Brady's veto is final
- **Abstention:** Permitted, does not count toward majority

### Emergency Process

For urgent agent needs, Brady may:
- Create agents directly (Council reviews retroactively)
- Fast-track proposals with 2-member review
- Suspend rules temporarily with documented rationale

## Quality Standards

### Agent Creation Requirements

Every new agent must have:
1. Agent file in `0-agents/custom-built-agents/` following `_template.md`
2. Clear Scope — what it IS and IS NOT for
3. Canonical Instruction — the one-liner that defines behavior
4. Reporting Line — who does it report to?
5. Handoff Rules — when does it defer to other agents?

### The Gold Medal Test

Before approving any agent, the Council asks:
> "Would this agent win a gold medal?"

Not "is this good enough?" — is this *excellent*?

## Council Meeting Cadence

- **As-needed** for agent creation proposals
- **Quarterly** for rule amendment review
- **Annually** for Council charter review
