## Purpose

Building a minimum viable product — software, app, or tool — from idea through first working version. Typically lives under the Ventures program.

## Roles Needed

| Role | Description | Suggested Draft From |
|------|-------------|---------------------|
| Lead | Owns delivery, scope, and coordination. Keeps the build focused on MVP, kills scope creep. | Claudine or Bo |
| Builder | Primary developer. Writes code, ships features. | engineering/frontend-developer, engineering/backend-developer, or relevant specialist |
| Reviewer | QA, code review, pressure-testing assumptions. Catches problems before they ship. | Phil (for strategy/coherence) + testing/ agent (for technical QA) |
| Designer | UX/UI if the product has a user-facing interface. | design/ux-researcher or design/ui-designer |

Minimum viable team: Lead + Builder. Add Reviewer and Designer as complexity warrants.

## Interaction Rules

- Builder proposes, Lead approves scope decisions
- Reviewer can block a ship if quality thresholds aren't met
- Designer delivers specs before Builder starts UI work — not after
- Daily async updates (what I did, what's next, what's blocked)
- Weekly sync with Lead to check scope against timeline

## Goals & Success Criteria

- Working product that demonstrates core value proposition
- Deployed and usable (not just local)
- At least 1 real user interaction (demo, beta tester, or paying customer)
- Completed within defined timeline

## Authority

- **Day**: Builder makes technical implementation decisions. Designer makes UX decisions.
- **Cycle**: Lead can adjust scope, cut features, or swap agents.
- **ARC**: Brady decides whether to continue, pivot, or kill the venture.
