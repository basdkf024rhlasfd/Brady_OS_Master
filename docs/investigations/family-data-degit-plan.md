### How the chatbot keeps rendering (graceful degradation)

`portal/src/lib/chat/kb-loader.ts` already reads each file with a per-file `try/catch` that returns `""` on miss (`loadKBFiles`, `loadUnifiedKB`). **So the moment a file is absent at runtime, the chatbot silently omits that section and still answers from the system prompt + whatever else resolved — partial/stale already beats blank, with zero code change.** That is the safety net that makes the untrack step non-catastrophic.

The *execution* work (deferred until Brady confirms scope) is to turn "absent" into "restored from Notion":

- **kb-loader change:** add a Notion-backed fallback keyed by the same file slugs used in `family.yml` / `financial-assistant.yml` routes. Simplest shape: a sibling loader (`kb-loader-notion.ts`) that, for a slug's KB config, queries a Notion data source (research-feed pattern) and returns the same `--- label ---\ncontent` section format; `loadKBFiles` tries disk first, then Notion, then `""`. Env-gated: **if `NOTION_API_KEY` is absent it no-ops to `""`** (build still compiles, page still renders).
- **Routes that must be repointed** (they name the now-removed files directly):
  - `family.yml` KB routes → the 12 sensitive family files (roster, weekly-schedule, budget-targets, activity-details, sweep-state, week-ahead, life-events, routines, decisions-log, open-loops, logistics-contacts) resolve via the Notion fallback.
  - `financial-assistant.yml` KB routes → the 5 financial kb files + `data.js` reference resolve via Notion / the new cockpit-data route.
- **Two direct static consumers that WILL break on untrack and must be handled with the same change:**
  1. `portal/public/financial-assistant/index.html:229` `<script src="data.js">` → `data.js` 404s → `window.COCKPIT_DATA` undefined → dashboard blank. **Must have the runtime replacement before/with removal.**
  2. `portal/src/app/(portal)/group/[id]/GroupPageClient.tsx:260` `fetch("/family/kb/01-family-roster.md")` (a UAT health-check) → will report "KB files: fail". Cosmetic (a diagnostic panel), but repoint it to the new runtime source.
- **Freshness checks to repoint:** `portal/src/lib/traffic-light/sources.ts` lists `public/financial-assistant/data.js` and `public/family/kb/12-open-loops.md` as staleness sources — update these to the runtime source or drop them.

## 3. What was done in this pass (non-destructive)

Added a clearly-commented **SENSITIVE FAMILY / FINANCIAL DATA** block to `portal/.gitignore`:

```
public/family/kb/
public/financial-assistant/data.js
public/financial-assistant/kb/
!public/financial-assistant/data.example.js
!public/financial-assistant/index.html
```

Verified with `git check-ignore --no-index`: new files under those paths are caught; `data.example.js` and `index.html` are preserved. **This prevents FUTURE commits only** — `.gitignore` does not untrack already-committed files, and modifications to already-tracked files still commit (tracked overrides ignore). Full protection needs the `git rm --cached` below.

**Scope note / tradeoff:** the block ignores the *whole* `public/family/kb/` and `public/financial-assistant/kb/` directories, which also sweeps up the 7 low-sensitivity family files (02, 04, 05, 08, 13, 14, 22). This is deliberate defense-in-depth: (a) sweeps rewrite every file in these dirs and any one can accrete sensitive data on the next run, (b) the whole dir is public over HTTP, (c) the target architecture is runtime-Notion-load for the whole KB anyway. If Brady prefers to keep the genuinely-safe files tracked so the chatbot retains partial disk-grounding with zero runtime work, swap the two directory lines for a surgical per-file ignore list (the 12 sensitive family files enumerated in §1). Recommendation: keep the directory-level ignore.

If approved, run in a dedicated window with all other harnesses paused (this re-SHAs everything and requires a force-push):

```bash

# 0) full backup first
git clone --mirror . ../brady-os-BACKUP-$(date +%Y%m%d).git

# 1) purge the paths from ALL history
git filter-repo --invert-paths \
  --path portal/public/family/kb \
```
