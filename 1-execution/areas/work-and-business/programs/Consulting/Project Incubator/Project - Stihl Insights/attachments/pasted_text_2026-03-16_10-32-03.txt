Dev Plan — Reliability Improvements for STIHL CI System

Epic 1 — Deterministic Command Execution

Problem:
Right now the system relies on natural language interpretation. That means commands like daily brief or stock pulse may occasionally produce partial or inconsistent outputs depending on how the model interprets the request.

User Story 1.1 — Command Router

As a CI system user (Rob)
I want commands like daily brief, stock pulse, and battlecard husqvarna to trigger deterministic workflows
So that I always receive the exact artifact expected.

Acceptance Criteria
	•	System detects command keywords with a command router
	•	Commands map to specific output templates
	•	Natural language interpretation is bypassed when a command is detected
	•	Router supports parameters (ex: battlecard husqvarna)
	•	Router logs which command was executed

Success Metric
	•	≥99% command execution accuracy

⸻

User Story 1.2 — Command Feedback

As a CI system user
I want confirmation of which command was executed
So that I know the system interpreted my request correctly.

Acceptance Criteria

System response header includes:

Command executed: DAILY_BRIEF
Template: Daily Intelligence Brief v1
Data sources: Yahoo Finance, FRED

Epic 2 — Structured Data Retrieval Layer

Problem:
The current system depends on ad hoc web search, which can produce inconsistent data retrieval.

User Story 2.1 — Market Data Adapter

As a CI system
I want a dedicated adapter for market data retrieval
So that stock and commodity data is reliable and consistent.

Acceptance Criteria

Supported endpoints:

stocks
commodities
currency

Example response structure:

{
  "ticker": "SWK",
  "price": 95.23,
  "daily_change": -1.2,
  "ytd_change": 3.4,
  "timestamp": "2026-03-16T11:15:00",
  "exchange": "NYSE",
  "source": "Yahoo Finance"
}

Success Metric
	•	All financial data pulled from structured API responses.

⸻

User Story 2.2 — Data Freshness Guardrails

As a CI system user
I want stale or unavailable data clearly flagged
So that executives do not rely on outdated intelligence.

Acceptance Criteria

If data age > 24 hours:

⚠️ STALE DATA — last updated March 14

If API fails:

❌ DATA UNAVAILABLE — source unreachable
