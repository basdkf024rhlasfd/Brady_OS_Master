# Design Brief For AI Design Agent

You are designing a single high-resolution infographic poster for the PauletteAI project.
Treat this as a premium internal "fight card" or Olympic event poster, not a SaaS dashboard, not a slide deck, and not a generic org chart.

## Objective

Turn the project summary below into a one-page visual that makes the PauletteAI project instantly legible:
- what the project is
- why it matters
- how the project is structured
- which agents are on the team
- what the timeline looks like
- what success looks like
- what rules the team is operating under

The poster should make the agents feel alive and cast-like, with a little game energy, while still reading like a serious operating artifact for a real consulting engagement.

## Deliverable

Produce:
1. One portrait-oriented infographic poster
2. High-resolution output suitable for review or print
3. A layout that is easy to update later by swapping text blocks, dates, and roster entries

Recommended production target:
- Portrait
- 2400 x 3200 px minimum
- 300 DPI if using a print workflow
- Strong enough contrast to read both on screen and on a printed page

## Visual Direction

Blend three references:
- UFC fight poster energy
- Olympic event-card structure
- premium strategy/war-room briefing clarity

Desired feel:
- bold
- compassionate but fierce
- high-status
- structured
- dramatic but not cheesy

The page should feel like a main-event matchup between Paulette's AI-powered shelter operation and the chaos of underfunded open-intake animal welfare — with BFAS as the active adversary — while still clearly showing the actual team and project mechanics.

## Content Priorities

The design must clearly surface these blocks in descending order:
1. Main Event
2. Tale Of The Tape
3. Starting Lineup
4. Timeline Board
5. Scoreboard
6. Corner Instructions
7. Arena Map

Use the content below as the source of truth. Do not invent new dates, metrics, agents, or project claims.

## Composition Guidance

- Lead with a strong hero treatment at the top
- Give the team roster enough space that each agent feels distinct
- Use stat-card treatment for the KPIs and key project numbers
- Make the timeline easy to scan in under 10 seconds
- Make the authority and instruction block feel like corner or coaching guidance
- Keep the arena map compact; it supports the story but should not dominate the page
- Prefer a poster composition over a document composition

## Style Constraints

- Do not make this look like enterprise software
- Do not use default dashboard cards everywhere
- Do not overfill the page with tiny text
- Do not hide the team roster below the fold or near the bottom
- Do not use generic AI-art fantasy imagery
- Do not lean on cliches like glowing circuits, robots, or holograms

If illustration is used, it should be graphic, minimal, and poster-like.

## Updateability Rules

Design this so future project posters can reuse the same system.
That means:
- modular sections
- repeatable type hierarchy
- reusable stat components
- clear roster slots
- text areas that can be updated without redesigning the full page

## Review Protocol

Assume I am the client and you are submitting `v1`.
If something is ambiguous, make the strongest reasonable design decision and label the assumption.
Do not ask for endless clarification before producing the first version.

After presenting `v1`, expect feedback in this form:
- what landed
- what feels off
- what needs more emphasis
- what should be cut

## Objective Acceptance Criteria

I will judge the design against these criteria:

| Criterion | Pass condition | Fail condition |
|-----------|----------------|----------------|
| Immediate clarity | In 5-10 seconds, I can identify the project, the customer, the team, and the deadline | I have to hunt for basic context |
| Poster energy | It feels like an intentional main-event poster, not a template or dashboard | It feels like slides, a website, or generic infographics |
| Team legibility | The agents feel like a cast with distinct roles and presence | The roster reads like a buried text table |
| KPI clarity | The success metrics and medal targets are obvious at a glance | KPI content is visually lost or overly text-heavy |
| Timeline clarity | I can understand past milestones and the next two target dates immediately | The timeline is confusing, buried, or visually weak |
| Information density | It feels rich but still readable from top to bottom on one page | It is either sparse and empty or crowded and exhausting |
| Updateability | I can see how the same layout could be reused next week or on another project | The composition is so bespoke that it would be painful to maintain |
| Tone control | The page is gameified and dramatic without becoming corny | The design slips into parody, sports-cliche overload, or gimmicks |
| Accuracy | All project facts match the source content below | The design invents or distorts project details |

## Quality Bar

This design is good if:
- it makes the PauletteAI project feel real, active, and high-value
- it gives the team a cast-like identity
- it makes the operating model legible in one page
- it looks strong enough that I would want every project in the OS to have one

This design is bad if:
- it looks like a startup dashboard
- it looks like a consultant slide
- it is all style with weak information hierarchy
- it is all information with no visual force
