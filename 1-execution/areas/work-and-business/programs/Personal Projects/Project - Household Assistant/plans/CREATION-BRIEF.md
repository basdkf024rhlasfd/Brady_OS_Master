## Context

Brady Smallwood built a static Walmart shopping list as a quick tool for his weekly family grocery run — interactive checkboxes, categorized by department, Walmart search deep links, embedded meal plan. He deployed it to mception.ai as a portal module (Phase 1 — complete).

The moment he used it, he saw the full vision: this isn't a shopping list, it's a family food operating system. The system should handle meal planning with nutrition guardrails, pantry inventory via phone photos, auto-generated grocery lists, price comparison, budget enforcement across all food spend (groceries + dining + school lunch funds), kid input and meal scoring, restaurant recommendations, Chrome-automated takeout ordering, recipe cards with AI chat integration, and a learning engine that optimizes across four variables: cost, ease, nutrition, and kid rating.

This is a personal project — no external client. The "customers" are Brady and his five kids. The system lives on mception.ai as a portal-native app, evolving from the static HTML already deployed. Quality matters more than speed. Each phase should be usable standalone before the next begins.

The project has natural integrations with existing Brady OS infrastructure: morning/evening sweeps (grocery signal detection), Chrome agent (Walmart/DoorDash/school portal automation), Notion (task/memory layer), and the mception.ai portal (UI surface).

## Open Questions

> Items the executing agent should resolve.

- **Kid request interface pattern**: Brady explicitly rejected Telegram/Telly for kids. Evaluate: (a) simple portal page with visual grid (no login needed, shared link), (b) Apple Shortcuts + iMessage, (c) shared Apple Note. Default: portal page with a shareable link. Escalate to Brady if: the chosen pattern requires kids to create accounts.
- **Walmart data access**: Walmart has no public API for order history. Evaluate: (a) Chrome agent scraping walmart.com while logged in, (b) email receipt parsing from Gmail, (c) manual CSV export. Default: Chrome agent. Escalate to Brady if: Walmart blocks automation or requires 2FA on every session.
- **School lunch portal**: Need to identify which school district / portal system (e.g., MySchoolBucks, SchoolCafe, PayPAMS). Escalate to Brady: which portal and login credentials.
- **Price comparison scope**: Brady mentioned Walmart. Confirm whether Sam's Club, Aldi, Harps, or other NWA stores are in scope. Default: Walmart only for Phase 3, expand later.
- **Caloric needs model**: Household of 6 — need approximate ages of kids to set age-appropriate caloric targets. Escalate to Brady: kids' ages (or age ranges).
- **Architecture evolution**: Phase 1 is static HTML in `public/`. Phases 2+ need API routes, data persistence, and dynamic UI. Plan: migrate to portal-native Next.js app (Pattern 2) at Phase 2 start. The static HTML becomes a fallback/archive.
